Project Presentation 3 – Agile Portfolio of Evidence

Linktank Technical Support Project

This section presents my Agile Portfolio of Evidence for Project Presentation 3. It demonstrates the planning, implementation, and reflection completed during my current industry placement at Linktank.

1. Agile Team Charter

Project Purpose

The purpose of this project is to improve the efficiency and quality of the Technical Support department at Linktank. By defining clear working agreements, values, and boundaries, the team aims to reduce ticket resolution times, improve customer satisfaction, and ensure a consistent support experience for clients using financial planning platforms like AdviceTech and Xplan.

Core Values

  • Communication: Maintain clear and patient communication with clients and advisors.
  • Accountability: Take ownership of queries and follow through to resolution.
  • Collaboration: Work together with the team (led by Mentor Abigail Rukuni) to solve complex software issues.
  • Security: Strictly verify information and follow security procedures during password resets.

Working Agreements

  • Daily stand-up meetings at 9:00 AM with the team.
  • All client interactions must be logged in the system.
  • Verify client details before performing any password resets or terminations.
  • Complex escalations must be routed to AdviceTech support promptly.
  • Blockers must be raised immediately during stand-up.

Evidence & Reflection

Evidence: Figure 1 – Agile Team Charter document; Figure 2 – Linktank induction and training notes.

Reflection: Creating the Agile Team Charter for the Linktank Technical Support team helped me understand the importance of establishing clear expectations in a professional environment. During my Capaciti training (Weeks 1-4), we worked on AI projects like the AI_Chatbot without a formal charter, which sometimes led to overlapping tasks. At Linktank, the charter provides a clear framework for how we work. It ensures that every team member understands the standards they must meet, especially regarding security and password resets. This experience has shown me that a strong team charter is a tool that improves communication, accountability, and overall team performance in a high-pressure support environment.

2. User Stories and Tasks

User stories were created to describe the Linktank support requirements from the perspective of the end user (the client/advisor) and the support agent.

User Story 1 – Password Resets (Priority: High)

As a Linktank client, I want to be able to reset my password quickly and securely so that I can regain access to my account.

  • Verify client identity over the phone or email.
  • Follow security procedures to reset the password.
  • Confirm with the client that they can log in successfully.
  • Log the interaction in the system.

User Story 2 – Advisor Mappings and FNA Recommendations (Priority: High)

As an Advisor, I want to ensure my client mappings and FNA recommendations are correct so that I can provide accurate financial advice.

  • Navigate the AdviceTech platform and Xplan system.
  • Test the mapping process to identify errors.
  • Guide the advisor through the step-by-step process over the phone.
  • Set up a remote session if necessary.

User Story 3 – Independent Client Access (Priority: Medium)

As a Support Agent, I want independent access to client profiles so that I can refresh them and resolve queries faster.

  • Get administrative access to the client database.
  • Test the profile refresh function.
  • Troubleshoot errors independently.
  • Escalate unresolved issues to AdviceTech support.

Evidence & Reflection

Evidence: Figure 3 – Documentation of user stories and tasks; Figure 4 – Screenshot of troubleshooting steps.

Reflection: Creating user stories helped me understand how to describe system requirements from the user's perspective rather than only focusing on technical details. In my Capaciti projects, like the Study-BuddyAI, I often approached development with a feature-first mindset. At Linktank, breaking each user story into smaller tasks made the work much easier to manage. For example, the simple task of resetting a password required verification, security checks, and client confirmation. This process improved my understanding of how a seemingly simple feature can involve multiple components. Overall, user stories helped me keep each improvement focused on the user's needs, while the individual tasks provided a clear plan for implementation.

What didn't go well: Multitasking between AdviceTech, Xplan, and the IFA site initially felt overwhelming. Some complex queries took longer to resolve while I was still learning the BA and Xplan integration.
